# 项目文件夹自动整理 Skill — 团队使用指南

> 一个通用的 AI Agent Skill，兼容 VS Code Copilot、Claude Code、Codex 等主流 AI 编程助手。**一句话**就能把杂乱的项目文件夹按公司标准的 6 阶段结构整理好，也能为新项目一键搭建标准目录骨架。

> 📂 Skill 源码在本仓库的 [`project-organizer/`](./project-organizer/) 目录下。论坛分享文章见 [`AI论坛分享-项目文件夹自动整理.md`](./AI论坛分享-项目文件夹自动整理.md)。

---

## 1. 它能为你做什么

| 痛点 | Skill 提供的能力 |
|------|------------------|
| 项目文件夹散落几十个零碎文件，找东西靠搜索 | **模式 A · 整理已有项目**：自动扫描 → 出迁移表 → 你确认 → 一键搬运 |
| 新项目不知道该建哪些文件夹，每个人建得都不一样 | **模式 B · 规划新项目**：一键创建 6 阶段 + raw/ 标准子目录 |
| 拿到一个文件不知道往哪放 | **模式 C · 单文件归类咨询**：直接告诉你该放哪个阶段 |
| 每天零散文件进来，不想频繁手动分类 | **模式 D · 清空 raw/ 投放区**：新文件全部丢 raw/，累积后一键分类 |
| 团队成员命名/归类口径不统一 | 全公司用同一套规则，跨人接手项目零成本 |

## 2. 标准 6 阶段结构（必须了解）

```
<项目名>/
├── 1-售前/
│   ├── 售前材料/      原始需求、调研报告、建设方案、技术澄清
│   ├── 招标文件/      招标方发出的文件、采购文件、招募文件
│   └── 投标文件/      我方应答材料、合作伙伴文件、技术标
├── 2-启动/
│   ├── 报价单/        报价、报价依据、财政证明
│   ├── 合同/          主合同、补充协议、保密承诺书
│   ├── 制作排期/      排期表、计划
│   └── 合作确认函/    商务确认函、中标通知、入围确认
├── 3-制作/
│   ├── 需求确认ppt/   内部需求确认、过程ppt、方案ppt
│   ├── 数据需求清单/  数据预审核、提资清单、数据对接清单
│   ├── 需求确认单/    自动生成的需求确认单、风险预告函
│   └── 前端低保真/    原型图、示意图、UI 草图
├── 4-交付/
│   ├── 交付结果/      源码、二开部署文档、最终交付物
│   └── 数据/          影像、DEM、BIM/CAD、模型、数据样本
├── 5-反馈/
│   ├── 会议记录/      会议纪要、会议视频
│   └── 需求修改/      需求变更、问题清单
├── 6-收尾/
│   ├── 汇报文档/      最终汇报ppt、交付截图
│   └── 验收单/        交付验收单、终验单、签字盖章版
├── raw/               ⭐ 原始文件投放区：新到的任何文件先丢这里，由 AI 自动分类
└── 其他/              暂时无法判断的文件
```

> 阶段编号 `1-` ~ `6-` 用于在文件资源管理器中保持顺序，请勿删除。

### ⚡ 关于 `raw/` 投放区（重要）

`raw/` 是个设计上的"**文件入口**"：

- 你从邮件/微信/合作方拿到任何新文件 → **无脑丢进 `raw/`**，不用思考该放哪
- 累积到一批后（一周/一个节点）→ 对 AI 说 **"清空 XX 项目的 raw"** → AI 自动按阶段分类迁走
- 迁移后 `raw/` 保留但变空，等你投下一批

这样你只需要管"收集"，不需要管"分类"。

## 3. 怎么用

> 假设你**完全没用过 AI 编程助手**，按下面步骤一步步做即可。

### 📦 准备工作：先安装一个 AI 编程助手（任选其一）

下面三个工具任选一个安装即可，**推荐 ① VS Code + Copilot**（界面友好，最适合新手）。

#### 选项 ① VS Code + GitHub Copilot（推荐新手）

1. 下载安装 **VS Code**：https://code.visualstudio.com/
2. 打开 VS Code，左侧点击"扩展"图标（四个方块），搜索 **GitHub Copilot**，点击安装
3. 安装完会提示登录 GitHub 账号（公司有提供账号就用公司的，没有可注册个人账号）
4. 登录后右下角会出现 Copilot 图标，按 `Ctrl+Alt+I` 即可呼出聊天框

#### 选项 ② Claude Code（命令行工具）

1. 安装 Node.js：https://nodejs.org/
2. 打开 PowerShell，输入：`npm install -g @anthropic-ai/claude-code`
3. 在项目文件夹里输入 `claude` 即可启动

#### 选项 ③ 已有其他 AI Agent

只要支持读取 `.github/skills/` 目录下的 SKILL.md 文件即可。

---

### 🗂️ 第一步：让 AI 自动安装 Skill（推荐方式）

> 💡 **核心思路**：你不需要手动建文件夹、复制文件。直接把下面的"安装指令"复制粘贴给 AI，它会自动从 GitHub 下载 Skill 并放到正确位置。

#### 通用安装指令（复制粘贴即可）

打开 AI Chat 窗口，**完整复制下面这段话**发给 AI：

```
请帮我安装 project-organizer 这个 skill：
1. 从 GitHub 仓库 https://github.com/51world-ai-copilot/TB-file-organize-tool 克隆或下载
2. 把 project-organizer 文件夹放到当前工作区的 .github/skills/ 下
3. 如果 .github/skills/ 不存在，请帮我创建
4. 安装完成后告诉我如何验证
```

AI 会自动执行：
- ✅ 检查当前工作区路径
- ✅ 下载 skill 文件
- ✅ 创建 `.github/skills/` 目录
- ✅ 把 skill 放到正确位置
- ✅ 告诉你下一步怎么验证

#### 如果想"全局安装"（所有项目都能用）

把这段发给 AI：

```
请帮我把 project-organizer skill 安装到个人级目录，让我所有项目都能用：
- 仓库地址：https://github.com/51world-ai-copilot/TB-file-organize-tool
- 我用的是 [VS Code Copilot / Claude Code / 其他]，请放到对应的用户级 skills 目录
- 如果目录不存在请创建
```

AI 会根据你说的工具自动选择正确路径（`~/.copilot/skills/` 或 `~/.claude/skills/` 等）。

#### 如果是从同事那里收到的 zip 包

把 zip 拖到任意文件夹后，告诉 AI：

```
我桌面上有一个 project-organizer-v1.0.zip，请帮我：
1. 解压它
2. 把里面的 project-organizer 文件夹放到当前工作区的 .github/skills/ 下
3. 删除临时的 zip 和解压残留
```

---

### 🔍 第二步：让 AI 验证安装成功

继续在 Chat 里发：

```
请检查 project-organizer skill 是否安装正确，并告诉我现在能不能正常调用。
```

AI 会：
- 检查 `SKILL.md` 文件是否存在
- 检查 frontmatter 格式是否正确
- 尝试列出 skill 内容并确认可调用
- 如果有问题会自动修复

---

### 💬 第三步：开始使用（用大白话指挥 AI）

打开 Chat 窗口，**像跟同事说话一样**直接告诉 AI 你想做什么：

| 你想做的事 | 完整复制下面这句话发给 AI |
|------------|---|
| 清理 raw/ 投放区（日常高频） | `帮我清空 "项目名" 的 raw 文件夹，按阶段分类迁移里面的文件` |
| 整理某个已有项目（一次性大整理） | `帮我按 6 阶段标准整理 "项目名" 这个项目` |
| 新建一个项目骨架 | `帮我新建一个项目叫 "项目名"，搭建标准目录结构` |
| 不确定一个文件放哪 | `这个文件 "xxx合同.pdf" 应该放在哪个阶段？` |
| 主动调用 Skill | 输入 `/project-organizer` 然后回车 |

> 💡 把上面的 `"项目名"` 换成你实际的项目文件夹名字，比如 `"抗战纪念馆"`。

---

### ✅ 第四步：审核 AI 的迁移计划再确认

**这一步非常重要！Skill 设计上不会偷偷动你的文件。**

AI 会先做这几件事，然后**停下来等你点头**：

1. **扫描** 你的项目目录，列出所有文件
2. **输出一张表格**，告诉你每个文件准备搬到哪里：
   ```
   原路径                              →  目标路径
   开工资料/合作确认函.docx              →  2-启动/合作确认函/
   合同/软件采购合同.pdf                →  2-启动/合同/
   会议记录视频.mp4                    →  ❓ 是会议视频还是数据样本？
   ```
3. **标记 ❓ 不确定项**，等你回答
4. **只有当你回复"确认"或"开始执行"**，AI 才会真正搬运文件

如果迁移表里有不对的地方，直接告诉 AI："第 3 行那个 pdf 应该放到 6-收尾/验收单 里"，AI 会修改方案再让你确认。

---

### 🆘 遇到问题怎么办？

最简单的办法：**把问题直接发给 AI**。例如：

```
我刚才让你装 project-organizer skill，但是输入 / 没看到这个选项，请帮我检查并修复
```

```
AI 没有自动调用 project-organizer skill，请你读取 .github/skills/project-organizer/SKILL.md 并按里面的工作流帮我整理项目
```

常见问题速查表：

| 问题 | 让 AI 怎么做 |
|---|---|
| `/` 没出现 `project-organizer` 选项 | "请检查 SKILL.md 是否在 `.github/skills/project-organizer/` 下，frontmatter 是否正确，并重启提示我" |
| AI 说"找不到这个 Skill" | "请确认 skill 文件夹名字是 `project-organizer`（不能改名），检查 SKILL.md 的 `name` 字段是否一致" |
| AI 直接动手没等我确认 | "请严格按 SKILL.md 的工作流：先扫描、出迁移表、等我确认后再执行" |
| 中文文件名变成乱码 | 看下方 **Q3** |
| 完全不会用，想要人手把手教 | 联系本文档作者，或在公司内部群里 @ 管理员 |

## 4. 实战示例

### 示例 A：整理已有项目

**你说：** 帮我整理 `服贸会海淀区AI场景展示` 这个项目。

**Skill 会：**
1. 列出 22 个文件、4 个文件夹
2. 给出迁移表，比如：
   ```
   开工资料/合作确认函0808.docx       → 2-启动/合作确认函/
   合同/【已用印】软件采购合同.pdf    → 2-启动/合同/
   会话厅poi文字.json                  → 4-交付/数据/
   AI协同空间...pptx                   → ❓ 是过程ppt还是汇报ppt？
   ```
3. 你回答疑问后 → 一键搬运 → 自动清理空文件夹 → 展示新结构

### 示例 B：新建项目

**你说：** 我要启动一个新项目叫 `北京XX地铁数字孪生`，先把目录搭好。

**Skill 会：** 一次性创建 19 个标准子文件夹，你后续放文件直接对号入座即可。

### 示例 C：单文件咨询

**你说：** 客户发来的 `需求变更说明V2.docx` 应该放哪？

**Skill 会：** "放到 `5-反馈/需求修改/`"。

### 示例 D：清空 raw/ 投放区（推荐日常用法）

**你说：** 这一周我往 `某某项目/raw/` 里丢了 8 个文件，帮我清空它。

**Skill 会：**
1. **只扫描 `raw/`**（不动其他阶段目录）
2. 生成迁移表：
   ```
   raw/合同扫描件.pdf            → 2-启动/合同/
   raw/会议纪要20260510.docx     → 5-反馈/会议记录/
   raw/意向书.docx               → ❓ 是招投标阶段还是合作确认？
   ```
3. 你确认 → 一键搬运
4. `raw/` **保留但变空**，等下一批

## 5. 安全保证（请放心使用）

| 担心 | 解决方案 |
|------|----------|
| 怕弄丢文件 | **永不删除文件**，只做"移动 + 创建空文件夹" |
| 怕同名覆盖 | 同名冲突自动加 `_冲突1` 或来源后缀（如 `_4.28`），保留两份 |
| 怕乱码文件名被改坏 | 发现 GBK 乱码（如 `鎶ヤ环鐢氶夋嵁`）会先列出来等你确认，绝不擅自重命名 |
| 怕大模型/数据被复制翻倍 | 使用 `Move-Item`，不复制只移动，不会占用双倍磁盘 |
| 怕误整理别的项目 | 只动你**显式指定**的项目，不会主动扫整个工作区 |

## 6. 常见问题

**Q1: 我已经按自己的方式建好了文件夹结构，会被强行覆盖吗？**
不会。Skill 看到的"原文件夹"如果有意义，会**整体保留层级**搬到对应阶段下，不会打散重命名。例如 `合作伙伴文件/某公司/...` 会整体迁入 `1-售前/投标文件/合作伙伴文件/某公司/...`。

**Q2: 阶段下的子文件夹用不到，可以不建吗？**
按目前规则会**全部建出来保持空文件夹**，方便团队成员一眼看到"还缺什么阶段的材料"。如果你团队希望按需创建，可以提需求让管理员调整 Skill。

**Q3: 一个文件横跨多个阶段，比如"既是售前调研也用作交付参考"，怎么办？**
按"**主要属于哪个阶段**"判断；如果实在不好分，放到 `其他/` 或在迁移确认时标 ❓ 让 Skill 询问你。

**Q4: 分类规则可以扩展吗？看到经常误判的情况怎么办？**
可以。规则全部写在 [`project-organizer/references/classification-rules.md`](./project-organizer/references/classification-rules.md)，关键词和示例一目了然。发现误判时告诉项目管理员，更新这个文件即可（更新后整个团队立刻生效）。

**Q5: Skill 能在不同电脑/工作区使用吗？**
当前是**工作区级别**（位于 `.github/skills/`），随项目仓库走。如果想个人级使用（所有工作区都生效），可以根据所用 Agent 复制到对应路径：
- VS Code Copilot: `~/.copilot/skills/`
- Claude Code: `~/.claude/skills/`
- 其他 Agent: `~/.agents/skills/`

**Q6: Agent 没有自动调用 Skill？**
- VS Code Copilot：确认输入 `/` 后能看到 `project-organizer` 备选项
- Claude Code / Codex：确认工作目录下存在 `.github/skills/project-organizer/SKILL.md`
- 描述更具体，比如直接说"按 6 阶段标准整理 XX 项目"
- 检查 `.github/skills/project-organizer/SKILL.md` 文件是否存在且格式正确

## 7. 目录约定 · 团队规范要点

为了让 Skill 工作得更顺畅，团队成员在新增文件时建议：

1. **新文件一律先丢 `raw/`**：不要发愁"这个文件该归哪"，收集阶段丢入 `raw/`，累积后调用 Skill 清空。
2. **文件名带阶段线索**：如 `XX项目_报价单_v3.pdf`、`XX_数据预审核.xlsx`，让 Skill 一眼能识别。
3. **不要在项目根目录乱放零散文件**：要么丢 `raw/`，要么直接放到对应阶段子目录。
4. **乱码文件名及时手动重命名**：如收到的 zip 解压后是 GBK 乱码，先解决再整理。
5. **保留合作方原始打包**：如某公司发来一个文件夹，整体搬到 `1-售前/投标文件/合作伙伴文件/某公司/`，不要打散。
6. **历史项目按需整理**：不要求一次整理全部历史项目，以"接手时整理一次"为节奏。

## 8. 反馈与迭代

- **发现误判 / 想加新分类？** 修改 [`project-organizer/references/classification-rules.md`](./project-organizer/references/classification-rules.md)
- **想调整阶段结构？** 修改 [`project-organizer/SKILL.md`](./project-organizer/SKILL.md) 中的"标准 6 阶段结构"和"命令模板"
- **完整工作流逻辑？** 全部写在 [`project-organizer/SKILL.md`](./project-organizer/SKILL.md) 中

> Skill 本身就是一个可读可改的 markdown 文件，**人和 AI 看的是同一份文档**，没有黑盒。
