# 项目文件夹自动化整理

## 标准 6 阶段结构

每个项目（即工作区根目录下的每个一级文件夹）必须遵循以下结构：

```
<项目名>/
├── 1-售前/
│   ├── 售前材料/         # 原始需求、调研报告、建设方案、技术澄清
│   ├── 招标文件/         # 招标方发出的文件、招募文件、采购文件
│   └── 投标文件/         # 我方应答材料、投标文件、报名材料、合作伙伴文件
├── 2-启动/
│   ├── 报价单/           # 报价、报价依据、财政证明
│   ├── 合同/             # 主合同、补充协议、框架协议、劳务合同
│   ├── 制作排期/         # 排期表、计划
│   └── 合作确认函/       # 商务确认函、入围确认、中标通知
├── 3-制作/
│   ├── 需求确认ppt/      # 内部需求确认、方案ppt
│   ├── 数据需求清单/     # 数据预审核、数据对接清单、需求整理清单
│   ├── 需求确认单/       # 自动生成的需求确认单
│   └── 前端低保真/       # 原型图、UI 草图、示意图
├── 4-交付/
│   ├── 交付结果/         # 最终交付物、源码、二开部署文档
│   └── 数据/             # 项目数据、影像、DEM、模型、json
├── 5-反馈/
│   ├── 会议记录/         # 会议纪要、视频
│   └── 需求修改/         # 需求变更、解决问题清单
├── 6-收尾/
│   ├── 汇报文档/         # 最终汇报ppt、交付截图
│   └── 验收单/           # 交付验收单、终验单、签字盖章版
├── raw/                  # ⭐ 原始文件投放区：所有新到的文件先丢这里，由 Skill 自动分类
└── 其他/                 # 无法归类的文件
```

阶段编号前缀（`1-` ~ `6-`）用于在文件资源管理器中保持顺序。

### 关于 `raw/` 投放区

`raw/` 是用户的**原始文件暂存区**，承担"文件入口"的角色：

- 用户拿到任何新文件（邮件附件、合作方发来的资料、扫描件等）**先无脑丢进 `raw/`**，无需思考分类
- 由 Skill 在用户触发时（模式 D）自动扫描 `raw/`，按分类规则迁移到对应阶段
- 迁移后 `raw/` 保持存在但变空，等待下一批新文件
- 这是**模式 B 新建项目时必须创建**的文件夹（已含在骨架中）
- **不要把 `raw/` 当成永久存储**，每次堆积一批后就调用 Skill 整理掉

## 何时使用

- 用户说"整理 XX 项目"、"把 XX 文件夹规范化"、"清理一下 XX" → **模式 A**
- 用户说"新建一个项目 XX"、"为 XX 搭建目录" → **模式 B**
- 用户问"这个文件应该放哪" → **模式 C**
- 用户说"整理 XX 项目的 raw"、"清空 raw"、"把 raw 里的文件分类" → **模式 D**
- 用户要求批量整理多个项目 → **模式 A** 循环
- 工作区出现大量散落在项目根目录的文件 → **模式 A**

## 工作流

所有模式均按"线性顺序"执行：每一步完成后再进入下一步，**绝不在用户确认前执行任何文件移动**。

### 模式 A：整理已有项目

流程：`确认项目 → 扫描 → 生成计划 → 用户确认 → 执行 → 清理 → 汇报`。

1. **确认目标项目**。若用户未明确指定，列出根目录下的项目并询问。
2. **扫描项目内容**。使用 `list_dir` 递归查看现有文件与子文件夹（深度 2-3 层即可）。
3. **生成迁移计划**。对每个文件/子文件夹按 [分类规则](./references/classification-rules.md) 判断目标阶段。
   - 输出一个表格：`原路径 → 目标路径`
   - 对不确定的项标注并归入 `其他/`，请用户确认
4. **请用户确认计划**。展示完整迁移表，明确告知用户哪些会被移动、哪些被合并。**不要在确认前执行任何 mv 操作**。
5. **执行迁移**。使用 PowerShell `Move-Item` 在终端执行：
   - 先 `New-Item -ItemType Directory -Force` 创建所有目标阶段子文件夹
   - 再批量 `Move-Item` 搬运
   - 中文路径需用双引号包裹
6. **清理空文件夹**。`Get-ChildItem -Recurse -Directory | Where-Object { -not (Get-ChildItem $_.FullName) } | Remove-Item`
7. **汇报结果**。展示整理后的目录树。

### 模式 B：规划新项目

1. **确认项目名**。
2. **创建标准骨架**。一次性创建上面 6 个阶段 + `raw/` + `其他/` 共 20 个子文件夹（含子分类）。
3. 在项目根目录创建一个简短的 `README.md`，列出阶段说明，**并明确告知用户：以后新文件直接丢到 `raw/` 即可，无需思考分类**。

### 模式 C：单文件归类咨询

用户问"X 文件放哪"时，参照 [分类规则](./references/classification-rules.md) 直接回答阶段路径，无需扫描整个项目。

### 模式 D：清空 raw/ 投放区（增量整理）

当用户说"整理一下 XX 项目的 raw"、"把 raw 里的文件分类"、"清空 raw" 等。

流程：`只扫 raw → 生成计划 → 用户确认 → 执行（保留 raw 目录） → 汇报`。

1. **只扫描 `<项目名>/raw/`**，不扫描其他阶段目录，避免误动已分类好的文件。
2. 按 [分类规则](./references/classification-rules.md) 对 `raw/` 内每个文件/子文件夹生成迁移表 `raw/xxx → N-阶段/子分类/`。
3. **请用户确认计划**（同模式 A）。
4. **执行迁移**。同名冲突时加后缀 `_rawN`（N 从 1 起递增），不要覆盖。
5. **保留 `raw/` 文件夹**（即使变空也不要删），方便用户继续投放下一批。
6. **汇报结果**：搬走多少个文件、还有多少 ❓ 项保留在 `raw/` 中等待用户决策。

> 与模式 A 的区别：模式 A 整理整个项目（一次性大整理），模式 D 只动 `raw/`（日常增量整理，频率高）。

## 关键约束

- **不得删除任何用户文件**。整理只做"移动 + 创建空文件夹"，遇到同名冲突时保留两份并加后缀 `_冲突N`（N 从 1 起递增，每次新冲突使用下一个未占用的数字，如 `_冲突1`、`_冲突2`、`_冲突3`），由用户决定。
- **保留原有有意义的子文件夹层级**。例如 `投标文件/某公司应答材料/` 整体迁入 `1-售前/投标文件/` 之下，不要打散。
- **乱码文件名先报告再处理**。如发现 GBK 乱码（`鎶ヤ环鐢氶夋嵁` 之类），先列出来交由用户确认是否需要重命名，不要擅自改名。
- **大文件/数据文件夹保持原样移动**，不要复制。
- **只整理用户显式要求的项目**，不要主动整理整个工作区，除非用户明确说"整理所有项目"。
- 编辑/移动含中文路径的文件时遵循用户内存中的 PowerShell 编码规则。

## 命令模板

新建项目骨架（PowerShell）：

```powershell
$proj = "项目名"
$stages = @(
  "1-售前\售前材料","1-售前\招标文件","1-售前\投标文件",
  "2-启动\报价单","2-启动\合同","2-启动\制作排期","2-启动\合作确认函",
  "3-制作\需求确认ppt","3-制作\数据需求清单","3-制作\需求确认单","3-制作\前端低保真",
  "4-交付\交付结果","4-交付\数据",
  "5-反馈\会议记录","5-反馈\需求修改",
  "6-收尾\汇报文档","6-收尾\验收单",
  "raw",
  "其他"
)
$stages | ForEach-Object { New-Item -ItemType Directory -Force -Path (Join-Path $proj $_) | Out-Null }
```
